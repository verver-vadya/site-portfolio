# site-portfolio

Сайт-портфолио verver: сайты, которые мы делаем, собраны как «вещи в каталоге». На первом экране кольцо из скриншотов работ, его крутят мышкой, пальцем, трекпадом или стрелками; ниже сетка работ с переключателем «Компьютер / Телефон», «Обо мне» и контакты. У каждой работы своя страница: задача, решение, скриншоты, ссылка на живой сайт.

Превью: https://verver-vadya.github.io/site-portfolio/ (после включения Pages, см. ниже).

Стек: [Astro](https://astro.build) без фреймворков, свой JS только у кольца (`src/scripts/ring.ts`). Шрифты Sofia Sans Condensed и Pixelify Sans (знак) лежат в репозитории, лицензии OFL рядом. Бэкенда нет.

## Добавить работу

Одна работа = одна папка в `src/content/cases/<папка>/`: файл `index.md` и скриншоты рядом. Кольцо, сетка, страница работы и карта сайта собираются из этих папок сами.

1. Снять скриншоты и создать заготовку (нужен Node.js 20+ и Chromium для Playwright):

   ```bash
   npm ci
   npx playwright install chromium   # один раз
   npm run case -- kare https://verver-vadya.github.io/site-kare/
   ```

   Скрипт снимает по три экрана на компьютере (1440×900) и телефоне (390×844) и, если работы ещё нет, создаёт `index.md` с полями в `[скобках]`. Повторный запуск обновляет только скриншоты.

2. Заполнить в `index.md` название, нишу, город, одну фразу о сайте и тексты «Задача» и «Решение». Поле `status: concept` ставит бирку «Концепт» (учебная работа), `client` — настоящий заказ. `order` задаёт порядок, `live: false` прячет ссылку, пока превью нет.

3. Открыть pull request. После слияния работа появится на сайте.

Проще всего попросить Claude: «добавь site-X в портфолио». Он сделает эти три шага сам.

## Запуск локально

```bash
npm ci
npm run dev       # http://localhost:4321/site-portfolio/
npm run build     # сборка в dist/
npm run preview   # посмотреть сборку
```

## Где что

- `src/pages/index.astro` — главная, `src/pages/cases/[slug].astro` — страница работы, `src/pages/404.astro`.
- `src/components/Ring.astro` и `src/scripts/ring.ts` — кольцо: панели, поворот, перетаскивание, клавиатура.
- `src/components/CaseCard.astro` — карточка работы на серой плашке.
- `src/styles/global.css` — токены: цвета, шрифты, отступы, движение.
- `src/content.config.ts` — какие поля есть у работы.
- `scripts/add-case.mjs` — снимки для новой работы.

Как ведёт себя кольцо: на компьютере в нём экраны компьютера, на телефоне экраны телефона; у каждой работы 1–3 экрана, кольцо добирается повторами до 12 панелей. Вертикальная прокрутка всегда листает страницу, кольцо при этом лишь слегка доворачивается. При выключенных в системе анимациях кольцо не доезжает при загрузке и не разгоняется, повороты кнопками проявляются на месте.

## Автопроверка

В каждом pull request сайт собирается и проверяется (Actions → «Проверка сайта»): битые ссылки, состояния кнопок, мелкие зоны нажатия, ошибки в консоли, ширины от 320 до 2560 px и масштаб Windows 125 % и 150 %, наложения, движение, заглушки. Подробности и чек-лист: `.github/check/check.mjs` и `.github/CHECKLIST.md`.

Локально:

```bash
BASE_PATH=/ npm run build
cd .github/check
npm ci
npm run check -- --site ../../dist           # черновик
npm run check:release -- --site ../../dist   # перед публикацией: заглушки тоже ошибки
```

Отчёт и скриншоты появятся в `.check/`.

## Публикация

- **Превью** собирается и публикуется на GitHub Pages после каждого пуша в `main`. Включить один раз в браузере: https://github.com/verver-vadya/site-portfolio/settings/pages → **Build and deployment** → **Source: GitHub Actions**.
- **Свой домен**: в `astro.config.mjs` поставить `site: "https://домен"`, собрать с `BASE_PATH=/ npm run build` и загрузить папку `dist/` на российский хостинг (Timeweb, Beget, Reg.ru). Страницу ошибки 404 указать `404.html`. Только после явного «да».

## Что заполнить перед публикацией

- Имя в «Обо мне» (`[ИМЯ]`), Telegram (`https://t.me/[ник]`) и почту (`[почта]`) в `src/pages/index.astro`.
- Знак `verver` в шапке и подвале, если сайт будет под другим именем.
